7.1 K-Means Clustering Centroid-Based

K-Means is a partition-based or centroid-based unsupervised learning algorithm used to group data into K distinct, non-overlapping clusters based on similarity.

Each group is formed by minimizing the distance between data points and the center of the group (called the centroid).

Higher K Value

Smaller, tightly packed clusters with greater localized detail.

Lower K Value

Larger, broader clusters that capture generalized patterns with less granularity.

Training Process

1
Choose K
Select the number of clusters to form upfront.
2
Initialize Centroids
Initialize K centroids randomly in the feature space as starting cluster centers.
3
Assign Points
Assign each data point to its nearest centroid based on distance.
4
Recalculate Centroids
Compute the mean position of all data points assigned to each cluster and move the centroid there.
5
Repeat Until Convergence
Repeat steps 3 and 4 until centroids stop moving (stabilize) or max iterations are reached.

Choosing the Optimal K Value

  • Visualization: Plot the data points as a 2D or 3D scatter plot and visually identify how many natural groupings are visible.
  • Elbow Method:
    Inertia Sum of Squared Distances to Centroids
    Plot inertia vs. K. Find the "elbow" point where the rate of inertia decrease slows down. This indicates the optimal K.
  • Silhouette Score: Measures how similar a point is to its own cluster compared to other clusters. The score ranges from -1 to +1, where a higher score indicates better cluster separation.
Advantages
  • Simple to understand and fast to implement.
  • Efficient with low computational cost; scales well to large datasets.
  • Works exceptionally well when clusters are spherical and well-separated.
Disadvantages
  • You must predefine the value of K.
  • Struggles with irregular-shaped or non-spherical clusters.
  • Highly sensitive to outliers, which can skew the mean and misplace centroids.
  • Initial centroid selection can drastically affect results (getting stuck in local minima).

7.2 DBSCAN Clustering Density-Based

DBSCAN (Density-Based Spatial Clustering of Applications with Noise) forms clusters based on the density of data points and automatically filters out outliers as noise.

It is especially useful when clusters are non-spherical, irregular, or contain noise, and it does not require you to predefine the number of clusters.

Parameters

Epsilon (eps)

The maximum radius distance to search for neighboring points.

Min Samples

The minimum number of points required within the eps radius to form a dense region.

How It Works

1
Identify Core Points
For each point, if the number of points within its eps radius ≥ min_samples, label it a Core Point.
2
Identify Border Points
A point with fewer neighbors than min_samples, but within the eps radius of a Core Point, is labeled a Border Point.
3
Group Clusters
Group all core points and their connected border points into single clusters.
4
Label Noise
Any point that is not a core point and is unreachable from any cluster is labeled as Noise (-1).
Advantages
  • No need to specify the number of clusters upfront.
  • Can find clusters of arbitrary or non-spherical shapes (e.g., rings, spirals).
  • Detects and isolates noise and outliers automatically.
Disadvantages
  • Needs careful tuning of the hyperparameters eps and min_samples.
  • Does not scale well to extremely large datasets due to distance computations.
  • Struggles when the density varies significantly across different clusters.
  • Performance drops in very high-dimensional spaces (curse of dimensionality).

7.3 HDBSCAN Clustering Hierarchical Density-Based

HDBSCAN (Hierarchical Density-Based Spatial Clustering of Applications with Noise) is a state-of-the-art improvement over DBSCAN, designed to handle clusters of varying densities.

Unlike DBSCAN, it does not require a single fixed epsilon threshold, allowing it to adapt to varying densities across the feature space.

Key Steps in HDBSCAN

1
Transform Space
Transform the mutual reachability distance space to make sparse points more distant and push dense regions closer.
2
Build Minimum Spanning Tree
Construct a minimum spanning tree representing the relative densities and distances between points.
3
Build Cluster Hierarchy
Create a hierarchical tree (dendrogram) of connected components based on varying density levels.
4
Condense & Extract
Condense the tree by removing small branches (less than minimum cluster size) and extract the most stable clusters.
Advantages
  • No need to predefine K or the eps parameter.
  • Highly robust in finding clusters of varying density.
  • Excels at isolating noise points in real-world, messy datasets.
  • Provides a stable hierarchical structure of clusters.
Disadvantages
  • Slightly slower computationally than standard DBSCAN.
  • Hierarchical outputs are harder to visualize and interpret for large datasets.
  • Requires setting the minimum cluster size parameter.

7.4 Agglomerative Clustering Hierarchical

Agglomerative Clustering is a **bottom-up hierarchical clustering method** that starts by treating every single data point as its own cluster and iteratively merges the closest pairs step-by-step until only one large cluster remains.

How It Works

1
Initialize N Clusters
Start with N clusters, where each data point is its own individual cluster.
2
Compute Distance Matrix
Compute the similarity or distance between all existing clusters.
3
Merge Closest Clusters
Identify and merge the two closest clusters into a single parent cluster.
4
Iterate to End
Repeat steps 2 and 3 until all points are merged into a single cluster or a predefined number of clusters is reached.
Visualizing the Hierarchy
The merge history is visualized using a tree-like structure called a Dendrogram. By cutting the dendrogram horizontally at a chosen distance threshold, you can extract the desired number of clusters without retraining.
Advantages
  • No need to specify the number of clusters upfront.
  • Can capture nested clusters and natural hierarchical relationships (ideal for taxonomies).
  • Works well with non-spherical shapes when using appropriate linkage criteria.
Disadvantages
  • Not scalable: extremely high computational and memory complexity ($O(N^3)$ or $O(N^2 \log N)$).
  • Sensitive to noise and outliers, which can force early incorrect merges.
  • Once two clusters are merged, the decision cannot be undone.
