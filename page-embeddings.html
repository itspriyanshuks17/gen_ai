1.0 Introduction Vector Spaces

Modern machine learning thrives on diverse, heterogeneous data types—images, text, audio, graph structures, and structured tables. Embeddings act as a unified mathematical translation layer, transforming unstructured real-world objects into dense, low-dimensional numerical vectors in a shared latent space.

Lossy Semantic Compression
Embeddings represent a form of lossy compression. They compress high-dimensional raw content into highly condensed vectors (e.g., 768 or 1536 float values) while strictly preserving critical semantic relationships.

1.1 Core Importance & Semantic Geometry

The name embeddings originates from mathematics, where one mathematical space is mapped, or embedded, into another. The core principle of embedding manifolds is that geometric distance mirrors semantic similarity.

Semantic Proximity

If two data objects are semantically similar (e.g., the word "computer" and a picture of a laptop), their vectors will lie close together in the embedding space.

Semantic Divergence

If objects have unrelated meanings (e.g., "computer" and "car"), their vectors will project far apart, exhibiting high geometric distance.

Intuition: Latitude & Longitude
Consider latitude and longitude as a simple 2D embedding of physical locations on Earth. Given two coordinate vectors, we can instantly calculate their geodesic distance or query nearby locations without looking at the map. In the same way, neural networks learn high-dimensional mappings for complex language and visuals.

1.2 Evaluating Embedding Quality Metrics

Evaluating embedding models requires quantitative benchmarks to measure their information retrieval capability. Rather than binary correctness, quality is measured on ranked retrieval performance over gold standard labeled datasets.

Key Evaluation Metrics

1
Precision@K
Measures what fraction of the top K retrieved documents are relevant.
Precision@K = Relevant Retrieved Documents / K
Example: If 7 of the top 10 retrieved chunks are relevant, Precision@10 is 0.7.
2
Recall@K
Measures what fraction of the total relevant documents in the corpus were successfully retrieved in the top K.
Recall@K = Relevant Retrieved / Total Relevant in Corpus
3
nDCG@K (Normalized Discounted Cumulative Gain)
Evaluates the ranked ordering of results, penalizing the model when highly relevant documents are placed lower in the list.
nDCG@P nDCG@P = DCG@P / IDCG@P   |   DCG@P = ∑ [ (2^rel_i - 1) / log_2(i + 1) ]
Dividing by the Ideal DCG (IDCG@P) normalizes the final score to a scale of 0.0 to 1.0.
Public Benchmarks
Standard benchmarks like **BEIR** (Heterogeneous Information Retrieval) and **MTEB** (Massive Text Embedding Benchmark) provide extensive criteria. Practitioners use standard evaluations via trec_eval or its Python wrapper pytrec_eval for consistent ranking checks.

1.3 Search & RAG Flow

A production **Retrieval-Augmented Generation (RAG)** pipeline divides embedding utilization into two phases:

1
Offline Index Creation
Documents are split into chunks → parsed → embedded using the RETRIEVAL_DOCUMENT task type of the model → loaded into a specialized high-performance Vector Database.
2
Online Query Execution
The user query is embedded using the RETRIEVAL_QUERY task type → a similarity search retrieves the closest document vectors from the database → the matching text chunks are inserted into the LLM prompt to generate an answer.

Architectures: Siamese vs. Asymmetric Dual Encoders

Symmetric (Siamese) Network

Uses a single, shared neural network to encode both queries and documents.

  • Best for sentence similarity or duplicate detection
  • Assumes queries and documents are structured identically
Asymmetric Dual Encoder

Trains two distinct neural network towers together: one optimized for queries and one for documents.

  • Essential for question-answering systems
  • Handles queries (short, informal) and documents (long, structured) mapping into a shared space

Production Semantic Search with Faiss & Vertex AI

This code example loads a health question dataset (**NFCorpus**), embeds documents and queries asynchronously using the Vertex AI `text-embedding-005` model, creates an L2 distance Faiss index, and evaluates accuracy metrics using `pytrec_eval`:

# 1. Helper function for batched semantic embedding
def embed_text(texts, model, task, batch_size=5):
    embed_mat = np.zeros((len(texts), 768))
    for batch_start in range(0, len(texts), batch_size):
        size = min(len(texts) - batch_start, batch_size)
        inputs = [TextEmbeddingInput(texts[batch_start+i], task_type=task) for i in range(size)]
        embeddings = model.get_embeddings(inputs)
        for i in range(size):
            embed_mat[batch_start + i, :] = embeddings[i].values
    return embed_mat

# 2. Initialize Vertex AI & Load Gecko/005 model
vertexai.init(project="PROJECT_ID", location="us-central1")
model = TextEmbeddingModel.from_pretrained("text-embedding-005")

# 3. Create document embeddings and load into Faiss L2 index
doc_embeddings = embed_text(docs, model, "RETRIEVAL_DOCUMENT")
index = faiss.IndexFlatL2(doc_embeddings.shape[1])
index.add(doc_embeddings)

# 4. Search and retrieve top nearest neighbors
query_embeddings = embed_text(questions, model, "RETRIEVAL_QUERY")
q_scores, q_doc_ids = index.search(query_embeddings, 10)

# 5. Evaluate retrieval quality via pytrec_eval
search_qrels = {
    q_ids[i] : {
        doc_ids[_id] : -1.0 * s.item() 
        for _id, s in zip(q_doc_ids[i], q_scores[i])
    } for i in range(len(q_ids))
}
evaluator = pytrec_eval.RelevanceEvaluator(qrels, {'ndcg_cut.10','P_1','recall_10'})
df = pd.DataFrame.from_dict(evaluator.evaluate(search_qrels), orient='index')
print(df.mean())
# P_1: 0.517  |  recall_10: 0.203  |  ndcg_cut_10: 0.402

1.4 Taxonomy of Embeddings

Depending on the format and relational structure of the raw inputs, embeddings fall into five specialized categories:

1. Text Embeddings

Mapping words, subwords, or full documents into dense vectors (Word2Vec, BERT, GTR, Gemini).

2. Multimodal Embeddings

Projecting multiple modalities (text, images, video) into a joint vector space (CLIP, SigLIP, ColPali).

3. Structured Data Embeddings

Embedding row structures in relational databases, categorical schemas, or transaction tables.

4. Graph Embeddings

Representing nodes, edges, and neighborhood connections inside complex network topologies (Node2Vec).

1.4.1 Text Embeddings & Tokenization

Text cannot be inputted directly into neural networks. It must undergo tokenization and categorical conversions:

1
Tokenization
Splitting the input string into smaller units called tokens (wordpieces, characters, punctuation).
2
Token IDs
Assigning a unique integer index in the range $[0, V-1]$ where $V$ is vocabulary cardinality.
3
One-Hot Encoding
Creating a sparse binary vector where the present token's index is 1, and all others are 0.
Limitation of One-Hot Encodings
Since Integer IDs or one-hot vectors are assigned arbitrarily, they are strictly categorical and **lack any semantic meaning** or relation. They treat "computer" and "calculator" as equidistant as "computer" and "banana". Dense embeddings are required to solve this.

1.4.2 Word Embeddings Precursors

Historically, context-free word embeddings laid the foundations for modern language models by operating on the principle that "a word is defined by its neighbors":

Word2Vec: CBOW vs. Skip-Gram

Continuous Bag of Words (CBOW)

Predicts a target middle word using the embeddings of surrounding context words as input.

  • Fast to train
  • More accurate for highly frequent words
Skip-Gram

Inverse of CBOW; uses a single middle word to predict surrounding context words.

  • Slower to train
  • Significantly more accurate for rare words

Global Statistics: GloVe & SWIVEL

  • GloVe (Global Vectors): Addresses Word2Vec's failure to capture corpus-wide global statistics by building a global word co-occurrence matrix and performing matrix factorization.
  • SWIVEL (Skip-Window Vectors with Negative Sampling): Speeds up training on huge corpora by dividing the co-occurrence matrix into sub-matrices, performing distributed matrix factorization in parallel across multiple systems using a specialized piecewise loss to handle unobserved pairs.

1.4.3 Document Embeddings Evolution

Document embeddings capture the semantic meaning of paragraphs and full texts. Their evolution split into two core eras:

1. Shallow Bag-of-Words (BoW) Era

Assumes a document is an unordered bag of tokens, completely ignoring word order and syntax:

  • LSA (Latent Semantic Analysis): Performs Singular Value Decomposition (SVD) on word co-occurrence matrices.
  • LDA (Latent Dirichlet Allocation): A probabilistic Bayesian model grouping documents into latent topics.
  • TF-IDF & BM25: Statistical weighting schemes based on term frequencies. BM25 remains a powerful baseline.
  • Doc2Vec: Extends Word2Vec by adding a trainable document/paragraph token vector that is concatenated with word tokens during context training.

2. Deeper Pre-trained Transformer Era

Leverages deep, bidirectional transformer blocks trained on massive unlabeled corpora:

  • BERT: Bidirectional Encoder Representations from Transformers. Uses Masked Language Modeling (MLM) and Next Sentence Prediction (NSP). The first token's contextual embedding ([CLS]) represents the entire sequence.
  • Sentence-T5 & GTR (General Text Embeddings): Leverage encoder-decoder structures to capture richer retrieval mappings.
  • Gemini Embeddings: Highly scalable models (e.g., text-embedding-004 and text-embedding-005) achieving top scores on BEIR benchmarks.
  • Matryoshka Embeddings: A highly optimized training method that forces the model to capture the most critical information in the first few dimensions. Downstream users can shrink a 768-dimension vector to 128 dimensions without retraining, saving massive vector storage costs.
  • Multi-Vector Models (ColBERT & XTR): Output distinct vectors for every token in a document rather than a single pooled vector, enabling highly granular token-level alignment checks.

1.4.4 Multimodal Embeddings

Multimodal embeddings project different modalities (such as images, text, and audio) into a **joint vector space**, enabling cross-modal retrieval (e.g., retrieving videos using text queries).

Unimodal Image Feature Vectors

Derived by passing images through CNNs or Vision Transformers (ViT) pre-trained on ImageNet and taking the penultimate pooling layer.

Joint Multimodal Spaces

CLIP or SigLIP architecture aligns visual features and textual embeddings into a unified manifold using dual image-text encoders trained contrastively.

ColPali Visual Scanning
Modern document retrieval approaches like **ColPali** leverage multimodal embeddings to index multi-modal documents (PDFs, slides) directly as visual page images. This bypasses highly error-prone OCR and layout parser pipelines by scanning and matching pages visually from text queries.

1.4.5 Structured & Graph Embeddings

Extending dense vector capabilities to relational tables and network systems:

Structured Row Mappings

Relational database tables lack global pre-trained models. Mappings must be trained application-specifically:

  • General Row-Wise Embeddings: PCA or Autoencoders map entire database rows into continuous embeddings, ideal for highly accurate anomaly detection in sensor arrays.
  • User-Item Collaborative Manifolds: recommendation systems map sparse user-product interactions (ratings, clicks) into a dense, shared embedding space, allowing immediate nearest-neighbor recommendations.

Graph Neighborhood Mappings

Graph networks (e.g., social connections, molecular bonds) are mapped into vectors where node features incorporate spatial topologies:

Structural Adjacency

If two nodes share an edge or exist inside the same localized neighborhood, their graph vectors will lie close together.

Algorithms

Popular algorithms like **DeepWalk** and **Node2Vec** use random walks along graph nodes to create sequential sequences, which are then passed into Word2Vec training loops.
