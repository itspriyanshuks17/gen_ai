3.1 Vector Similarity Metrics Math

Vector search shifts information retrieval from literal keyword matching to semantic meaning. Misspelled, differently phrased, or cross-modal inputs (like images and text) can be mapped and matched in real-time by computing distance in vector space.

Given a query vector $\vec{q}$ and a document vector $\vec{d}$, three mathematical metrics are primarily used to compute similarity:

Euclidean Distance (L2)

Calculates the physical geometric distance between two points in Cartesian space.

d(u,v) = √∑(uᵢ - vᵢ)²
⚠️ Highly sensitive to magnitude; poor for high dimensions.
Cosine Similarity

Measures the cosine of the angle between two vectors, completely ignoring their length magnitudes.

cos(θ) = (u • v) / (||u|| ||v||)
✓ Excellent for high-dimensional document semantic matches.
Inner / Dot Product

Calculates the algebraic projection of one vector onto another. Equivalent to cosine similarity when vectors are normalized to unit length.

u • v = ∑ uᵢvᵢ
✓ Standard metric for scale-optimized models (ScaNN).

3.2 Approximate Nearest Neighbor (ANN) Algorithms

An exact brute-force search compares a query vector with every document inside the database. This scales as $\mathcal{O}(N)$, rendering it unacceptably slow for production datasets. **Approximate Nearest Neighbor (ANN)** search trades a tiny margin of accuracy for massive $\mathcal{O}(\log N)$ speedups.

Locality Sensitive Hashing (LSH) & Decision Trees

  • Locality Sensitive Hashing (LSH): Maps similar vectors into the same hash bucket with high probability using random partition hyperplanes. Similarity search only requires hashing the query and searching linearly inside that specific bucket.
  • KD-Trees: Partitions space along dimension medians, forming a binary decision search tree. Ineffective for high-dimensional vectors.
  • Ball-Trees: Partitions space into nested spherical hyper-spheres, bypassing KD-Tree dimensional issues by structuring regions based on radial distance.
from sklearn.neighbors import NearestNeighbors
from lshashing import LSHRandom

# 1. Naive brute-force search
nbrs_brute = NearestNeighbors(n_neighbors=2, algorithm='brute').fit(docs)
brute_dist, brute_ind = nbrs_brute.kneighbors(query)

# 2. Optimized Ball-Tree ANN search for high-dimensional space
nbrs_ball = NearestNeighbors(n_neighbors=2, algorithm='ball_tree').fit(docs)
ball_dist, ball_ind = nbrs_ball.kneighbors(query)

# 3. LSH Hashing KNN search
lsh = LSHRandom(docs, hash_size=4, parallel=True)
lsh.knn_search(docs, query, k=2, parallel=True)

3.2.1 Hierarchical Navigable Small Worlds (HNSW)

HNSW represents a state-of-the-art graph-based ANN algorithm. It structures vector spaces into a multi-layered proximity graph where the graph links are spread hierarchically.

The top layers have the longest, sparsest links (acting as express lanes), while the lowest layer (Layer 0) holds all points linked with short, dense connections. The search zooms in chronologically:

1
Express Entry
Enter at the top layer and greedily traverse the long links to find the node most similar to the query.
2
Descend Layer
Once a local minimum is reached, drop down to the corresponding node in the layer below.
3
Granular Converge
Repeat the localized search on the dense bottom layer (Layer 0) to fetch the top $K$ nearest neighbors in sub-linear $\mathcal{O}(\log N)$ time.
import faiss

M = 32     # Graph connections degree: higher M = better recall, slower indexing
d = 768    # Vector dimensions

# Build HNSW index with flat L2 distance
index = faiss.IndexHNSWFlat(d, M)
index.add(document_embeddings)

# Execute HNSW Approximate Nearest Neighbors search
scores, indices = index.search(query_embedding, k=2)

3.2.2 ScaNN (Anisotropic Quantization)

Developed by Google, ScaNN (Scalable Approximate Nearest Neighbor) is an industry-leading ANN library. It is integrated natively inside Google Vertex AI Vector Search, AlloyDB, Spanner, and Cloud SQL.

How ScaNN Works

1
Space Partitioning
During training, it groups the vector space into $C$ distinct partitions/clusters. *Rule of thumb:* set partitions count equal to the square root of total vectors count.
2
Search Space Pruning
At query time, ScaNN calculates similarity against partition centroids and selects only the top $P$ partitions, completely **pruning the rest of the database** and cutting search computations by orders of magnitude.
3
Anisotropic Vector Quantization
To calculate distance quickly inside the remaining partitions, it compresses vectors into quantized codes. Unlike traditional product quantization, ScaNN's **anisotropic quantization** penalizes parallel quantization errors less than perpendicular errors, drastically improving recall.
4
Final Rescoring
Optionally takes the top $K'$ candidates retrieved and recalculates their exact distances using full-precision weights to return an incredibly accurate final rank. 
import tensorflow_recommenders as tfrs

# Initialize ScaNN search index layer
scann = tfrs.layers.factorized_top_k.ScaNN(
    distance_measure='dot_product',
    num_leaves=2000,            # Total number of partitions
    num_leaves_to_search=100    # Partitions to search (pruning ratio)
)

# Load dataset and build the index
scann = scann.index_from_dataset(embedded_docs)
scores, doc_ids = scann(embedded_query, k=2)

3.3 Vector Databases & Hybrid Search

While ANN algorithms provide indexing functions, **Vector Databases** operationalize them for enterprise production workloads. They manage full CRUD lifecycles, real-time index updates, data consistency, horizontal scaling, backups, and security access controls.

Hybrid Search: Combining Semantic & Syntactic Matching

Embeddings are great at capturing overall semantic meaning, but **fail on exact literal matches, product serial numbers, or domain-specific IDs** which might be out-of-vocabulary for the neural models. Production databases solve this via Hybrid Search:

Semantic Search (Dense)

Uses HNSW or ScaNN to query dense semantic vectors, capturing conceptual meanings.

Full-Text Search (Sparse)

Uses inverted indexes (BM25) to search for exact keyword matching, strings, and code IDs.

Hybrid Fusion & Reranking
The database executes both semantic dense search and traditional sparse search in parallel. The raw results are merged using **Reciprocal Rank Fusion (RRF)** and passed to a cross-encoder model for final reranking.

3.4 Operational Considerations inside Production

Deploying vector databases at enterprise scale involves addressing four core operational challenges:

  • Vector Mutation & Drift: As embedding models are updated (e.g., upgrading from `gecko@003` to `text-embedding-005`), **all stored vectors become obsolete and cannot be compared**. Re-embedding billions of historical items is extremely expensive. Production pipelines must balance upgrade cycles and leverage automated, background re-indexing queues.
  • Pre-filtering vs. Post-filtering:
    • *Post-filtering:* Runs ANN search first, then filters out items that don't match metadata tags. ⚠️ Risks returning fewer than $K$ results if matches are filtered out.
    • *Pre-filtering:* Filters the metadata index first, then executes the ANN search on only that subset. ✓ Preferred method, natively optimized inside modern databases.
  • OLTP vs. OLAP Database Split:
    • *Operational (OLTP):* For real-time updates and transaction guarantees, run vector plugins inside core operational engines like **AlloyDB, Spanner (pgvector), or Cloud SQL Postgres**.
    • *Analytical (OLAP):* For massive batch calculations and large-scale data queries, run vector search directly inside **Google BigQuery**.

3.5 RAG Grounding & Latency Reduction

Retrieval-Augmented Generation (RAG) is the primary application for embeddings, designed to mitigate LLM hallucinations and bypass costly retraining by feeding fresh context in the prompt:

1
Source Grounding
Retrieves relevant context chunks from the vector database. If the database returns no semantic matches, the system gracefully prints a refusal (e.g., "I do not know") rather than letting the LLM hallucinate.
2
Source Attribution
Always returning the exact source IDs along with the final text, allowing users or automated LLM auto-evaluators to crosscheck and verify the grounded claims.

Production RAG Pipeline with LangChain & Vertex AI Vector Search

This implementation sets up a scalable HNSW tree index endpoint, streams text documents to the GCS bucket, and connects a `gemini-pro` QA chain to perform grounded retrieval:

from google.cloud import aiplatform
from langchain_google_vertexai import VertexAIEmbeddings, VectorSearchVectorStore, VertexAI
from langchain.chains import RetrievalQA
from langchain.prompts.chat import ChatPromptTemplate, SystemMessagePromptTemplate, HumanMessagePromptTemplate

# 1. Initialize Vertex AI
aiplatform.init(project=PROJECT_ID, location=REGION, staging_bucket=BUCKET_URI)
embedding_model = VertexAIEmbeddings(model_name="text-embedding-005")

# 2. Deploy Google Matching Engine ANN tree index (HNSW graph)
my_index = aiplatform.MatchingEngineIndex.create_tree_ah_index(
    display_name="hnsw_index",
    dimensions=768,
    approximate_neighbors_count=150,
    distance_measure_type="DOT_PRODUCT_DISTANCE",
    index_update_method="STREAM_UPDATE"
)

# 3. Create public index endpoint and deploy HNSW graph
my_endpoint = aiplatform.MatchingEngineIndexEndpoint.create(display_name="endpoint", public_endpoint_enabled=True)
my_endpoint = my_endpoint.deploy_index(index=my_index, deployed_index_id="deployed_01")

# 4. Initialize Vector Store and add text content
vector_store = VectorSearchVectorStore.from_components(
    project_id=PROJECT_ID, region=REGION, gcs_bucket_name=BUCKET,
    index_id=my_index.name, endpoint_id=my_endpoint.name,
    embedding=embedding_model, stream_update=True
)
vector_store.add_texts(texts=["The sun sets in the west.", "Mat is on the floor."])

# 5. Connect Vector Store to Gemini-Pro QA chain
retriever = vector_store.as_retriever(search_kwargs={'k': 1})
qa_chain = RetrievalQA.from_chain_type(
    llm=VertexAI(model_name="gemini-pro"), 
    chain_type="stuff", 
    retriever=retriever, 
    return_source_documents=True
)

# 6. Execute RAG grounded QA
result = qa_chain("Where does the sun set?")
print(result['result'])
# "The sun sets in the west." [Source: "The sun sets in the west."]
