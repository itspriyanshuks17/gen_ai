Chapter 01

Introduction to Large Language Models

Index › Chapter 01
CH 01

Why Language Models Matter

What is a Language Model?

A language model predicts the probability of a sequence of words. Given a prefix ("The most famous city in the US is…"), it assigns high probabilities to likely next words ("New York") and low probabilities to nonsensical ones ("laptop").

📚 Definition
Large Language Model (LLM)
An advanced AI system implemented as a deep neural network, trained on massive amounts of text data to learn intricate language patterns — enabling machine translation, creative text generation, question answering, summarization, and complex reasoning.
Before Transformers: RNNs

Prior to the transformer revolution, Recurrent Neural Networks (RNNs) — specifically LSTM and GRU architectures — were the dominant approach for sequence modeling.

  • RNNs process sequences sequentially, making parallelization hard
  • Generate hidden states based on previous state + current input
  • Theoretically infinite context, but suffer from vanishing gradient problem
  • Compute-intensive, slow to train at scale
The Transformer Advantage
⚡
Parallelization

Processes all tokens simultaneously via self-attention — dramatically faster training than sequential RNNs.

Key Win
🔭
Long-range Context

Self-attention allows every token to "see" every other token directly, capturing distant dependencies.

Context
⚠️
Quadratic Cost

Self-attention is O(n²) in sequence length — limits context window size in original architecture.

Tradeoff
Why LLMs Are Important

LLMs achieve a massive performance boost over previous NLP models across tasks requiring complex reasoning. They display emergent behaviors — abilities not directly trained for.

🔑 Key Concept
Emergent Behavior
Foundational LLMs trained on diverse data perform well out of the box and can generalize to tasks they were never explicitly trained on (zero/few-shot). This emerges from scale — not specific task design.
  • Fine-tuning adapts a pre-trained LLM to specific domains — requires far less data than training from scratch
  • Prompt Engineering guides the model via carefully composed inputs — no training required
  • Key applications: translation, code generation, text classification, summarization, Q&A, chatbots
Chapter 02

The Transformer Architecture

Index › Chapter 02
CH 02

Building the Transformer

📅 Origin
The transformer was developed at Google in 2017 (Vaswani et al., "Attention is All You Need") as a sequence-to-sequence model for translation. It replaced RNNs with a pure attention mechanism.
Input Preparation & Embedding

Before tokens enter the transformer, raw text undergoes a multi-step preparation pipeline:

  1. Normalization (Optional) Standardizes text by removing redundant whitespace, accents, and inconsistent formatting.
  2. Tokenization Breaks sentence into words or subwords; maps each to an integer token ID from a vocabulary (using BPE or Unigram methods).
  3. Embedding Converts each token ID into a high-dimensional vector representation (learned during training via a lookup table).
  4. Positional Encoding Adds position information to each token's vector — since self-attention is order-agnostic without it.
Encoder vs. Decoder
📥
Encoder

Processes the full input sequence into contextual representations Z. Uses bidirectional self-attention — every token can attend to every other.

BERT-style
📤
Decoder

Generates output token-by-token using masked self-attention (can only see past tokens) + cross-attention to encoder output Z.

GPT-style
🔀
Decoder-Only

Most modern LLMs use only the decoder — skipping the encoder. Generates output directly from input via masked self-attention alone.

Modern LLMs
🔑 Key Insight
Majority of Modern LLMs = Decoder-Only
GPT, Gemini, LLaMA, Gopher, PaLM, etc. all use the decoder-only variant. It forgoes encoder-decoder separation and directly generates output from input via masked self-attention.
Feedforward & Normalization Layers

Each transformer block contains:

  • Multi-Head Attention — computes relationships between tokens
  • Add & Norm (Residual + Layer Norm) — stabilizes training, helps gradient flow
  • Feedforward Layer — two linear transformations + non-linear activation (ReLU/GELU) applied position-wise
  • Another Add & Norm after feedforward
📐 Formula
Residual Connection
Output = LayerNorm(x + Sublayer(x))
// 'Add' = skip connection; 'Norm' = layer normalization
// Prevents vanishing gradients in deep stacks
Mixture of Experts (MoE)

MoE is an architecture that combines multiple specialized sub-models ("experts") to tackle complex tasks efficiently.

  • Experts — individual sub-models (typically transformer-based), each specializing in a subset of inputs
  • Gating Network (Router) — learns to route inputs to the most relevant expert(s), producing a probability distribution over experts
  • Combination Mechanism — combines expert outputs weighted by gate probabilities (typically a weighted average)
  • Sparse Activation — only a subset of experts activate per token → huge computational savings
💡 MoE Advantage
More Parameters, Less Compute
MoE models have massive total parameter counts but only activate a fraction per forward pass. GLaM (1.2T params) used ⅓ the energy of GPT-3's training while outperforming it.
Chapter 03

The Self-Attention Mechanism

Index › Chapter 03
CH 03

How Attention Works

Self-attention is the core innovation of transformers. It enables each token to dynamically "attend" to all other tokens, capturing relationships and context that span the entire sequence.

The Q, K, V Framework

Each input embedding is projected into three specialized vectors via learned weight matrices:

❓
Query (Q)

Represents the current token asking: "Which other words in the sequence are relevant to me?"

Wq matrix
🔑
Key (K)

Represents how each token identifies itself — a label for determining relevance to other queries.

Wk matrix
💎
Value (V)

Holds the actual content information of each token — what gets aggregated into the output.

Wv matrix
Step-by-Step Self-Attention Computation
  1. Project embeddings → Q, K, V Multiply each input embedding by learned matrices Wq, Wk, Wv to produce query, key, and value vectors for every token.
  2. Calculate attention scores Compute dot products of each Query with all Keys: Score(Q, K) = Q · Kᵀ. High dot product = high relevance.
  3. Scale & Normalize Divide scores by √d_k (dimension of keys) for numerical stability. Apply softmax to convert scores to probabilities (attention weights).
  4. Weighted value aggregation Multiply each Value vector by its attention weight, then sum. This produces a context-aware representation for each token.
📐 Attention Formula
Scaled Dot-Product Attention
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V

// Q = Queries matrix, K = Keys matrix, V = Values matrix
// d_k = dimension of key vectors (for stability scaling)
// Output Z = context-aware representation of input sequence
Multi-Head Attention: Power in Diversity

Instead of one set of Q/K/V matrices, multi-head attention runs multiple attention "heads" in parallel, each potentially focusing on different aspects of relationships.

  • Each head learns different Q, K, V projections → captures different relationship types
  • Outputs from all heads are concatenated then linearly projected
  • Gives the model a richer, multi-perspective representation of the input
  • Crucial for tasks needing nuanced language understanding: translation, summarization, Q&A
💡 Example
Coreference Resolution via Attention
In "The tiger jumped because it was thirsty" — self-attention correctly identifies that "it" and "tiger" refer to the same entity by assigning them high attention weights to each other.
Layer Normalization & Residual Connections
⚖️
Layer Normalization

Computes mean and variance of activations in a layer and normalizes them. Reduces covariate shift, improves gradient flow, speeds up convergence.

🔄
Residual Connections

Propagates the input directly to the output: Output = x + Sublayer(x). Makes optimization easier and prevents vanishing/exploding gradients in deep networks.

Chapter 04

Training & Data Preparation

Index › Chapter 04
CH 04

How Transformers Are Trained

📌 Key Distinction
Training vs. Inference
Training: modifies model parameters using loss functions and backpropagation.
Inference: uses fixed parameters to generate predictions — no weight updates occur.
Data Preparation Pipeline
  1. Data Cleaning Filtering, deduplication, and normalization of raw text to remove noise and redundancy.
  2. Tokenization Convert text to tokens using Byte-Pair Encoding (BPE) or Unigram tokenization. Generates a vocabulary — the model's "language".
  3. Train/Test Split Data split into training set (for weight updates) and test set (for performance evaluation).
Tokenization Methods
🔤
Byte-Pair Encoding (BPE)

Iteratively merges the most frequent pair of characters/subwords. Balances vocabulary size with coverage of rare words.

Most Common
📊
Unigram Tokenization

Uses a probabilistic model to find the most likely tokenization. Can produce multiple segmentations with different probabilities.

Probabilistic
Training Loop & Loss Function
  • Sample batches of input sequences from the training dataset
  • Feed into transformer → generate predicted output sequences
  • Measure prediction error with cross-entropy loss
  • Calculate gradients of the loss via backpropagation
  • Optimizer (Adam/AdamW) updates parameters based on gradients
  • Repeat until convergence or target token count reached
Training Tasks by Architecture
Architecture Pre-training Task Example Models
Decoder-Only Language Modeling (next-token prediction) Input: "the cat sat on" → Predict: "the" GPT series, Gemini, LLaMA
Encoder-Only Masked Language Modeling (MLM) Input: "The [MASK] sat on the mat" → Predict: "cat" BERT
Encoder-Decoder Sequence-to-Sequence supervised Translation, summarization, Q&A Original Transformer, T5
Context Length Tradeoffs
⚠️ Tradeoff
Longer Context = Better Performance but Higher Cost
Longer context lengths allow the model to capture more complex relationships — but require more memory and compute, slowing both training and inference. The right context length depends on task requirements and available resources.
Scaling Laws

Performance follows predictable power laws as model size (N), data (D), and compute (C) scale. The Chinchilla paper (2022) overturned earlier wisdom:

📐 Chinchilla Scaling Law
Compute-Optimal Scaling
For a 100× increase in compute (C):
→ Increase model size N by ~10× (not 28.8× as previously thought)
→ Increase data size D by ~10× (not just 3.5×)

// Near-equal scaling of parameters AND data is optimal
// Previous Kaplan et al. over-weighted model size vs. data
Chapter 05

The GPT & BERT Era (2018–2020)

Index › Chapter 05
CH 05

Pioneering Architectures

2018 · OpenAI
GPT-1 — Decoder-Only Pre-training
Key Innovations:
1. Unsupervised pre-training + supervised fine-tuning — showed this beats supervised-only training. Trained on BooksCorpus (5GB, 7000+ books).
2. Task-aware input transformations — converts structured tasks (entailment, QA) into formats the model can parse without task-specific architectures.

Limitations: Repetitive text on out-of-distribution prompts; poor multi-turn reasoning; limited long-passage cohesion.
2018 · Google
BERT — Bidirectional Encoder Representations
Architecture: Encoder-only. Cannot generate text — focused purely on language understanding.

Training Tasks:
1. Masked Language Modeling (MLM) — randomly mask tokens, predict originals using bidirectional context
2. Next Sentence Prediction (NSP) — predict if sentence B follows sentence A

Strength: Captures context from both left and right simultaneously → excellent at NLU tasks (QA, sentiment, NLI).
2019 · OpenAI
GPT-2 — Scaled Up to 1.5B Parameters
Scale-up: 10× more parameters (1.5B vs 117M), 10× more data (WebText: 40GB, 45M Reddit pages with ≥3 karma).

Zero-Shot Learning: GPT-2's landmark achievement — performing tasks like translation, summarization, and reading comprehension without any explicit supervision or fine-tuning.

Finding: Zero-shot performance increased log-linearly with model capacity.
2020 · OpenAI
GPT-3 — 175B Parameters & Few-Shot Learning
Scale: 175B parameters (vs. GPT-2's 1.5B) — a 116× jump in size.

Few-Shot Capability: Can understand and execute tasks from just a few examples in the prompt — no task-specific fine-tuning needed.

Release: Made available as a commercial API (unlike GPT-2, which was initially withheld).

InstructGPT (GPT-3 variant): Fine-tuned with SFT + RLHF. A 1.3B InstructGPT outperformed 175B raw GPT-3 on human evaluations — showing alignment matters more than raw scale.
GPT-3.5 & GPT-4 Highlights
ModelKey FeatureContext WindowNote
GPT-3.5 Turbo Code understanding + generation; dialogue-optimized 16,385 tokens input / 4,096 output Optimized for chat
GPT-4 Multimodal (text + image input); advanced reasoning 128,000 tokens input / 4,096 output Matches/exceeds human on many tasks
Chapter 06

The Scaling Era (2021–2022)

Index › Chapter 06
CH 06

Gopher, Chinchilla & PaLM

2021 · Google
LaMDA — Language Model for Dialogue Applications
Designed for open-ended, natural conversations — not just isolated responses. Trained on dialogue-focused data to encourage conversational flow. Unlike GPT's multi-task generalism, LaMDA prioritized conversational depth and breadth.
2021 · DeepMind
Gopher — 280B Parameters with Data Quality Focus
Dataset: MassiveText — 10TB, 2.45B documents (web, books, news, GitHub). Trained on only 300B tokens (12% of dataset) with aggressive deduplication and filtering.

Optimization: Warmup LR → cosine decay; gradient clipping to max norm 1; as model size increased, LR decreased and batch size increased.

Result: Outperformed prior SotA on 81% of tasks. Strong on knowledge-intensive tasks, weaker on abstract reasoning (e.g., algebra).
2021 · Google
GLaM — First Sparse Mixture-of-Experts LLM
Scale: 1.2 trillion parameters — but only activates a fraction per token (sparse activation).

Efficiency: Used only ⅓ the energy of GPT-3's training and half the FLOPs for inference — while outperforming GPT-3 overall. First major demonstration of MoE's practical value at LLM scale.
2022 · DeepMind
Chinchilla — Rewriting Scaling Laws
The Finding: Prior LLMs were massively undertrained relative to their size. Optimal scaling requires equal increases in data and model size with compute budget.

Result: Chinchilla (70B, same compute as Gopher 280B) uniformly outperformed Gopher, GPT-3, and Megatron-Turing NLG (530B) while being 4× smaller — cheaper to run.

Impact: Shifted the field toward scaling data quality/quantity alongside parameters.
2022–2023 · Google
PaLM & PaLM 2 — Pathways Architecture
PaLM: 540B parameters. Trained via the Pathways system across two TPU v4 Pods. State-of-the-art on GLUE and SuperGLUE benchmarks. Strong on common sense, arithmetic, joke explanation, code, translation.

PaLM 2 (May 2023): Architectural and training improvements made it more capable than PaLM with fewer total parameters. Foundation for Google Cloud Generative AI commercial models.

OpenAI o1 — Reasoning via Chain-of-Thought RL
💡 Novel Approach
Internal Chain-of-Thought + RL
The o1 series uses reinforcement learning to develop an internal "chain-of-thought" process — deliberating extensively before generating a final response. Results: 89th percentile on Codeforces, top 500 on AIME, surpasses PhD-level accuracy on GPQA (physics/bio/chem).
DeepSeek — RL Without Labeled Data (GRPO)

DeepSeek achieved o1-comparable reasoning performance using a novel RL approach that eliminates the critic model:

  • DeepSeek-R1: Multi-stage training — cold-start SFT → pure RL → rejection sampling → combined SFT+RL → final polish
  • Matches or exceeds o1 on many benchmarks. Despite open weights, effectively closed-source (no training data transparency)
Chapter 08

Fine-Tuning Methods

Index › Chapter 08
CH 08

Adapting Pre-trained LLMs

LLMs go through multiple training stages. Pre-training (weeks/months, massive compute) gives general language ability. Fine-tuning then specializes the model at far lower cost.

Stage 1: Supervised Fine-Tuning (SFT)
📋 Definition
Supervised Fine-Tuning (SFT)
Training an LLM on a small, high-quality, human-curated dataset of input-output pairs. Each data point = a prompt + its ideal target response. Dataset is much smaller than pre-training data, of higher quality.

SFT use cases:

  • Instruction tuning — follow instructions (summarize, write code, write a poem)
  • Dialogue tuning — multi-turn conversational data (question-answer format)
  • Safety tuning — reduce bias, discrimination, toxic outputs via RLHF guardrails
Stage 2: Reinforcement Learning from Human Feedback (RLHF)

RLHF aligns LLM responses with human preferences — making them more helpful, truthful, and safer. Unlike SFT (only positive examples), RLHF can penalize bad outputs.

  1. Train a Reward Model (RM) Initialize with a pre-trained (often SFT'd) model. Fine-tune on human preference data: given two responses A and B, humans label which is preferred.
  2. Generate responses with policy LLM The LLM generates candidate responses to prompts.
  3. Score with Reward Model RM scores each response on dimensions like helpfulness, truthfulness, safety.
  4. Update policy via RL A policy gradient algorithm (e.g., PPO) updates the LLM to maximize reward model scores.
🤖
RLAIF

RL from AI Feedback — uses another AI model to generate preference labels instead of humans. Scales better than pure human annotation.

Scalable
📐
DPO

Direct Preference Optimization — removes the need for a separate reward model. Directly optimizes the policy on preference data.

Simpler
Parameter Efficient Fine-Tuning (PEFT)

Full fine-tuning of billion-parameter models is expensive. PEFT techniques add/modify a tiny fraction of parameters to achieve comparable results at a fraction of the cost.

MethodHow It WorksAdvantageCost vs. Performance
Adapter Add small adapter modules to each transformer layer; only train adapters Few new parameters; original weights unchanged Low cost, good performance
LoRA Approximate weight updates with two small low-rank matrices; freeze original weights Plug-and-play; minimal inference latency overhead Very efficient; near full-finetune quality
QLoRA LoRA + quantized base weights Even greater memory efficiency Best cost; slightly lower than LoRA
Soft Prompting Learn continuous "soft prompt" vectors prepended to input; freeze model As few as 5 tokens; enables mixed-task inference Cheapest; slightly lower quality
📊 Performance Ranking
Quality vs Cost
Quality: Full Fine-tuning > LoRA > Soft Prompting
Cost: Soft Prompting < LoRA < Full Fine-tuning
All three are more memory-efficient than traditional full fine-tuning and achieve comparable performance for most tasks.
Chapter 09

Prompting & Sampling Techniques

Index › Chapter 09
CH 09

Guiding LLM Outputs

Prompt Engineering Techniques

Prompt engineering is the art of composing inputs to guide LLMs toward desired outputs — without modifying model weights. It's the most accessible way to improve LLM behavior.

🎯
Zero-Shot Prompting

Provide task description only — no examples. The LLM relies entirely on pre-trained knowledge. Fast, but less reliable for complex tasks.

No examples
📝
Few-Shot Prompting

Provide 3–5 carefully chosen input-output examples before the actual query. Guides the model's response format and style significantly.

3–5 examples
🔗
Chain-of-Thought (CoT)

Prompt includes step-by-step reasoning examples. Model generates its own reasoning chain before answering. Dramatically improves complex reasoning.

Reasoning
🧠 Advanced CoT Variants
Tree-of-Thoughts & Least-to-Most
Tree-of-Thoughts: Explores multiple reasoning paths using a search algorithm. Useful for game trees and combinatorial problems.

Least-to-Most Prompting: Guides the model to solve subproblems of increasing complexity. Output of one subproblem feeds into the next.
Sampling Techniques

Sampling determines how the model selects the next token. Different strategies trade off quality, creativity, and diversity.

TechniqueHow It WorksBest ForTradeoff
Greedy Search Always selects highest-probability token Factual, deterministic output Repetitive, predictable
Random Sampling Sample proportionally to probability distribution Creative, diverse text Can produce nonsense
Temperature Scale probability distribution by temperature T Tuning creativity level High T=diverse; Low T=predictable
Top-K Sample from top K most probable tokens Controlled randomness K controls diversity
Top-P (Nucleus) Sample from tokens summing to probability P Adaptive diversity Adapts to model confidence
Best-of-N Generate N responses; select best by reward model Short snippets, code, logic N× compute cost
💡 Practical Guidance
Temperature Settings
Temperature → 0: Near-deterministic. Best for factual Q&A, code generation, extraction.
Temperature → 1: Standard sampling. Good balance for conversational responses.
Temperature > 1: High creativity/diversity. Good for brainstorming, creative writing.
Task-Based Evaluation Framework

A tailored evaluation framework is essential when moving LLM applications from prototype to production:

  • Evaluation Data — Custom dataset mirroring production traffic; enriched with real interactions and synthetic edge cases
  • Development Context — Evaluate the entire system including RAG, agentic workflows, not just the LLM output
  • Definition of "Good" — Move beyond single-answer similarity; use rubrics capturing business outcomes and desired output properties
📊
Traditional Metrics

Quantitative metrics (BLEU, ROUGE, accuracy) comparing to reference answers. Objective but penalizes valid unexpected solutions.

👤
Human Evaluation

Gold standard — nuanced assessment of complex outputs. Expensive and slow to scale.

🤖
LLM Autoraters

Use an LLM to judge outputs. Scalable, can work with or without references. Requires calibration via meta-evaluation against human judgments.

Chapter 10

Accelerating Inference

Index › Chapter 10
CH 10

Making LLMs Faster & Cheaper

As LLMs scale, inference cost and latency become critical. Two primary resources: memory and computation. Optimization methods fall into two categories:

📐
Output-Approximating

May slightly change model outputs in exchange for significant speed/cost gains. Includes quantization and distillation.

Quality Tradeoff
🎯
Output-Preserving

Guarantee identical model outputs — pure engineering wins. Include Flash Attention, prefix caching, speculative decoding.

Quality Neutral
Output-Approximating: Quantization

Reduce numerical precision of model weights and activations from 32-bit floats to 8-bit or 4-bit integers.

  • Reduces memory footprint — fit larger models on same hardware
  • Reduces communication overhead within/across chips in distributed inference
  • Enables faster arithmetic — TPUs/GPUs natively support lower-precision operations
  • QAT (Quantization-Aware Training) — incorporate quantization during training → model recovers quality losses
📊 Benchmark
Quantization Quality Impact
Benoit Jacob et al. reported a 2× speed-up for only a 2% accuracy drop on FaceDetection (MobileNet SSD). In many use cases, quality impact is negligible.
Output-Approximating: Distillation

Train a smaller student model to mimic a larger teacher model. Smaller models + same data = worse than larger models, but distillation bridges the gap.

  • Data Distillation — use teacher to generate synthetic training data for student; more data → better student performance
  • Knowledge Distillation — align student's output token distributions to teacher's (more sample-efficient)
  • On-Policy Distillation — teacher provides feedback on student's generated sequences via RL setup
Output-Preserving: Flash Attention

Self-attention is O(n²) in sequence length — a major bottleneck. Flash Attention (Tri Dao et al.) optimizes this by being IO-aware:

  • Minimizes data movement between slow HBM (high bandwidth memory) and fast SRAM/VMEM
  • Fuses multiple attention operations to maximize fast memory utilization
  • Mathematically exact — zero quality loss
  • Achieves 2–4× latency improvement in attention computation
Output-Preserving: Prefix Caching (KV Cache)

The costliest part of LLM inference is the prefill phase — computing attention key/value scores for all input tokens. These are cached as the KV Cache.

💾 How It Works
Prefix Caching Explained
The KV cache from a previous inference request is stored (memory or disk) and reused if the same prefix appears in a new request — skipping the expensive recompute.

Best use cases: Multi-turn chatbots (conversation history unchanged), large document/code uploads (file unchanged between queries).
⚠️ Gotcha
Keep Prefixes Stable!
Changing the prefix (e.g., putting a fresh timestamp at the very beginning of each request) invalidates the cache for ALL tokens that follow — eliminating all caching benefits.
Output-Preserving: Speculative Decoding

The decode phase (token-by-token generation) is memory-bound and inherently serial — each token must wait for the previous. Speculative decoding breaks this bottleneck:

  1. Drafter runs ahead A small, fast "drafter" model generates N candidate tokens (e.g., 4 tokens) very quickly.
  2. Main model verifies in parallel The large main model verifies all N hypotheses simultaneously — using spare compute capacity.
  3. Accept maximum valid prefix The longest accepted hypothesis is used. If drafter was wrong at token 3, tokens 1-2 are accepted, token 3 is corrected.
⚡ Latency Example
Speed Calculation
Without speculative decoding: 3 tokens × 10ms = 30ms
With speculative decoding: (3 × 1ms drafter) + 10ms main = 13ms
→ 2.3× speedup with zero quality loss

Batching & Parallelization
  • Batching — run multiple requests simultaneously on the same hardware (best on decode phase, which is not compute-bound)
  • Sequence Parallelism — split input sequence across devices
  • Pipeline Parallelism — split transformer layers across devices
  • Tensor Parallelism — split individual layer computations across devices
  • Key challenge: inter-device communication overhead can erode gains if strategy is wrong

📋 Summary — Key Takeaways
What to Remember
1. Transformer architecture = basis for all modern LLMs. Dataset quality matters as much as parameter count.

2. Fine-tuning order matters: Instruction Tuning → Safety Tuning → RLHF/RLAIF for alignment. SFT captures task essence; RLHF shifts distribution toward desired behavior.

3. Inference efficiency is an active research area — many methods reduce latency/cost with minimal quality impact; some (Flash Attention, prefix caching, speculative decoding) are quality-neutral.

4. Prompt engineering is powerful — combine with the right sampling parameters (temperature, top-K, top-P) for task-specific optimization.
