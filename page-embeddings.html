Understanding
Embeddings

From the mathematical intuition to practical types — text, image, multimodal, structured data, and graph embeddings — with evaluation metrics and key algorithms.

What Are Embeddings?

Embeddings are numerical representations of real-world objects — text, speech, images, videos — expressed as low-dimensional vectors. The term "embedding" comes from mathematics, where one space is mapped (embedded) into another.

🔑 Core Intuition

Think of latitude and longitude. Any location on Earth maps to just two numbers, yet these two numbers let you measure distance and find nearby places. Embeddings do the same for abstract data — objects that are semantically similar end up geometrically close in the vector space.

The original BERT model embeds text into a vector of 768 numbers, compressing the infinite space of possible sentences down to a manageable 768 dimensions, while preserving semantic relationships. If the word "computer" and "laptop" are similar in meaning, their embeddings will be close in vector space.

Why Embeddings Matter

Compact Representation
Lossy compression that retains the important semantic properties. Much smaller than one-hot encoding (which requires a dimension per vocabulary term).
Semantic Comparison
Two vectors can be compared numerically — their distance measures how semantically different the underlying objects are.
Cross-Modal Search
Joint embeddings place text and images in the same vector space, enabling text-to-image or image-to-text retrieval.
Downstream ML Features
Use as ready-made, dense feature vectors for classifiers, recommenders, and other ML models.
⚠️ Important — Model Compatibility

Embeddings from different models are NOT compatible. You must use the same model for both indexing and querying. Mixing models gives meaningless similarity scores.

Evaluating Embedding Quality

Evaluation requires labeled datasets where the correct relevant documents are already known. The goal: embeddings that bring similar objects close together and dissimilar objects far apart.

Core Retrieval Metrics

Precision@k
P@k = (# relevant docs in top k) / k
Example: 7 out of 10 retrieved docs are relevant → P@10 = 0.7
Recall@k
R@k = (# relevant docs retrieved) / (total relevant in corpus)
Example: 3 of 6 total relevant docs retrieved → R@20 = 0.5
DCG — Discounted Cumulative Gain
DCG@p = Σᵢ₌₁ᵖ relᵢ / log₂(i + 1)
The denominator penalizes items lower in the ranking. Favors putting the most relevant result first.
nDCG — Normalized DCG
nDCG = DCG / IDCG
IDCG = ideal ordering. nDCG ∈ [0, 1.0], allows comparison across queries.
📊 Public Benchmarks

BEIR — the standard benchmark for retrieval tasks. MTEB (Massive Text Embedding Benchmark) covers more tasks including classification and clustering. Use trec_eval or pytrec_eval (Python) for consistent measurement.

Text Embeddings

Text embeddings are central to NLP. They capture the meaning of natural language for use in text generation, classification, sentiment analysis, semantic search, and more. They fall into two main categories: token/word embeddings and document embeddings.

Tokenization — The First Step

Before embedding, text must be tokenized — split into meaningful units — then each token assigned a unique integer ID.

Text → Embedding Pipeline
Input String
→
Tokenization
→
Integer Indexing
→
Embedding Lookup
Token Types
Wordpieces, characters, whole words, numbers, punctuation. Subword tokenization (used in BERT) handles unknown words gracefully.
One-Hot Encoding
Binary vector — 1 for word present, 0 for absent. Simple but results in sparse, high-dimensional vectors with no semantic meaning.

Word Embeddings

Precursors to modern document embeddings. Context-free — the same word always gets the same vector regardless of sentence context. Major algorithms: Word2Vec, GloVe, SWIVEL.

Word2Vec

Principle: "The semantic meaning of a word is defined by its neighbors." Words that frequently appear together get similar embeddings.

CBOW — Continuous Bag of Words
  • Predicts the middle word from surrounding context
  • Agnostic to word order in context window
  • Faster to train
  • Slightly more accurate for frequent words
Skip-Gram
  • Predicts surrounding words from the middle
  • Inverse setup to CBOW
  • Slower to train
  • Better for rare words and small datasets

Word2Vec produces a matrix of shape (vocab_size × embedding_dim) used as a lookup table. Extended to sub-word level in FastText.

Limitation: Word2Vec captures local statistics (within a sliding window) but misses global co-occurrence statistics across the whole corpus.

GloVe & SWIVEL

GloVe
  • Builds a global co-occurrence matrix
  • Uses matrix factorization
  • Captures both global AND local word statistics
  • Useful for a broad range of NLP tasks
SWIVEL
  • Skip-Window Vectors with Negative Sampling
  • Also uses co-occurrence matrix
  • Handles unobserved co-occurrences with piecewise loss
  • Considerably faster via distributed training
  • Subdivides matrices into sub-matrices for parallel factorization

Document Embeddings

Embed entire paragraphs or documents into dense vectors. Two main stages in the evolution:

Stage 1 — Shallow Bag-of-Words (BoW) Models

Assume documents are unordered collections of words. Fast but miss word order and context.

ModelApproachKey Feature
LSASVD on word-document co-occurrence matrixCaptures latent topics
LDABayesian network / probabilistic topic modelInterpretable topics
TF-IDFTerm frequency × inverse document frequencySimple, still competitive (BM25)
Doc2VecExtends Word2Vec with paragraph ID vectorDense doc embedding via neural net (2014)
⚠️ BoW Limitations

BoW models ignore word order and semantic context. "Dog bites man" and "Man bites dog" would produce identical embeddings. This is why deep neural network models became necessary.

Stage 2 — Deep Pretrained LLMs

Key advances that made deep models transformative:

  1. Bidirectional deep neural networks (not just left-to-right)
  2. Massive pre-training on unlabeled text corpora
  3. Subword tokenizers (handle unseen words gracefully)
  4. Fine-tuning for specific downstream NLP tasks

BERT (2018) — The Breakthrough

Bidirectional Encoder Representations from Transformers. Pre-trained on masked language modeling (MLM) — randomly mask tokens, predict them using both left AND right context.

Pre-training Objectives
Masked Language Model (MLM): randomly mask ~15% of tokens; model must predict them using full bidirectional context. Next Sentence Prediction (NSP): predict whether two sentences are consecutive.
Output
Contextualized embedding for every input token. The [CLS] token's embedding is used as the whole-document representation. Same word = different embeddings in different contexts (unlike Word2Vec).

📈 BEIR Score Progress

Original BERT models scored 10.6 on BEIR. Current 2025 Google embeddings via a simple API call now score 55.7 — a 5× improvement, achieved in under 7 years.

Matryoshka Embeddings

Allow users to select how many dimensions to use. Lower-dimensional prefixes are trained to be meaningful, so you can truncate the vector for speed without a complete quality collapse. Named after nested Russian dolls.

Image & Multimodal Embeddings

Unimodal Image Embeddings
  • Train CNN or Vision Transformer on large image classification task (e.g., ImageNet)
  • Use penultimate layer as the embedding
  • That layer learned discriminative features
  • Can be fine-tuned for other tasks
Multimodal / Joint Embeddings
  • Map text AND images into the same vector space
  • Train with cross-modal contrastive loss
  • Enables text-to-image retrieval and vice versa
  • ColPali: retrieves from document images without OCR
🔑 Joint Embedding Insight

In a joint embedding space, the text "a photo of a cat" and an actual photo of a cat should be close together, while both should be far from a photo of a dog. This enables cross-modal search at scale.

Structured Data Embeddings

Structured data has a defined schema (database tables). Unlike text/images, there are usually no pre-trained models — you must create the embedding model for your specific application.

General Structured Data
  • Create row-level embeddings using dimensionality reduction (PCA etc.)
  • Use case: anomaly detection on sensor data
  • Use case: fewer labeled samples needed for supervised tasks
User/Item Structured Data
  • Maps users AND items into the same embedding space
  • Interaction data (ratings, clicks) used as training signal
  • Drives recommendation systems
  • Can be combined with text/image embeddings

Graph Embeddings

Represent not just an object but also its neighborhood in a graph. In a social network, each person's embedding captures both their own attributes and who they're connected to.

Core Idea
If two nodes are connected by an edge, their vectors should be similar. Predict new connections, classify nodes, or recommend items.
Popular Algorithms
DeepWalk, Node2vec, LINE, GraphSAGE — each with different trade-offs between local and global neighborhood information.

Applications: node classification, link prediction, community detection, knowledge graph completion, fraud detection, recommendation systems.

🔑 When to Use Graph Embeddings

When your data has an inherent graph structure — social networks, knowledge graphs, citation networks, supply chains — graph embeddings typically outperform standard text or structured data embeddings.
