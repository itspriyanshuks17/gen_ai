Dual Encoder Architecture

Modern embedding models use a dual encoder (two-tower) architecture. Each tower encodes one type of input, and the two towers are trained jointly to map related inputs close together in vector space.

🔑 Why Two Towers?

A question and its answer are semantically complementary, not identical. A single encoder (siamese network) treats them symmetrically — but their linguistic style differs greatly. Two separate encoders, trained together, capture this asymmetry better.

Contrastive Loss

The standard training objective for embedding models. Takes a tuple of <input, positive target, [optional] negative targets>.

🔑 What Contrastive Loss Does

Pulls positive pairs together (a question and its correct answer) and pushes negative pairs apart (a question paired with wrong answers). Over many iterations, the vector space learns the geometry of semantic similarity.

Positive Pairs
Question + its correct answer / document. The model is rewarded for making these embeddings close.
Negative Pairs
Question + an incorrect or unrelated document. The model is penalized if these are close. Hard negatives (plausible but wrong) are especially valuable for training.
In-Batch Negatives
Efficient strategy: treat other items in the same training batch as negatives. Scales well and is used in SimCSE and many modern models.
Hard Negative Mining
Actively select the most difficult negatives (semantically similar but incorrect). Forces the model to learn finer distinctions.

Training Stages

Modern embedding models typically go through two stages, mirroring foundation model training:

Stage 1 — Pre-training (Unsupervised)

Learn general representations from large unlabeled corpora. In practice, most models today skip building from scratch and instead initialize from existing foundation models (BERT, T5, GPT, Gemini, CoCa) to leverage their pre-existing world knowledge.

Foundation ModelParametersKey Characteristic
BERT110M–340MBidirectional, masked language modeling
T5up to 11BText-to-text transfer transformer
PaLM540BPathways-trained, multilingual
GeminiVariesMultimodal, powers Gecko embeddings
GPT / LlamaVariesDecoder-only, generative architecture

Stage 2 — Fine-tuning (Supervised)

Adapt the pre-trained model to the specific embedding task using labeled data. Can be single-phase or multi-phase.

📌 Fine-tuning Options

Frozen encoder: freeze the pre-trained model, only train a new task head. Best when training data is small. Full fine-tuning: update all weights. More data-hungry but potentially higher quality. Adapter-based: insert small trainable layers, keep base model frozen.

To add downstream task capability (classification, NER), add task-specific layers (e.g., softmax classifier) on top of the embedding model output.

Training Data

Training embedding models requires question–document pairs where the relevance is known. The right dataset depends heavily on the domain.

Domain Specificity Matters
  • Medical apps need medical QA data
  • Legal apps need legal document pairs
  • General benchmarks (NFCorpus, BEIR) provide a starting point
  • Domain shift from training → inference degrades quality
Data Generation Methods
  • Human labeling: highest quality, very expensive
  • LLM-generated synthetic data: scalable, increasingly high quality
  • Model distillation: use a teacher model's outputs
  • Hard negative mining: programmatic selection

Synthetic Training Data with LLMs

A major breakthrough: instead of paying human annotators, use an LLM to generate thousands of question–document pairs. This was central to how Google's Gecko model achieved state-of-the-art results.

🔑 LLM-Generated Training Data Pipeline

1. Take a large document corpus. 2. Prompt an LLM to generate plausible questions for each document. 3. Use the generated (question, document) pairs for contrastive training. 4. Optionally use LLM judges to evaluate answer quality. This approach scales training data collection cost-effectively.

Gecko — Google's State-of-the-Art Embedding Model

Gecko, released on Google Vertex AI, uses the Gemini model backbone and achieves the best results on public benchmarks as of early 2025. Key innovations:

LLM Backbone
Initialized from Gemini, giving it access to the world knowledge learned during Gemini's massive pre-training.
Synthetic Data
Used an LLM to generate a large set of (question, document) pairs for fine-tuning training. Detailed in the Gecko paper from Google DeepMind.
BEIR Score
Achieves 55.7 average on BEIR — compared to 10.6 for the original BERT models. Available via a simple Google Vertex API call.
Task Types
Supports: RETRIEVAL_QUERY, RETRIEVAL_DOCUMENT, SEMANTIC_SIMILARITY, CLASSIFICATION, CLUSTERING. Use the right task type for your use case.
# Using Gecko via Vertex AI — task type matters!
from vertexai.language_models import TextEmbeddingInput, TextEmbeddingModel

model = TextEmbeddingModel.from_pretrained("text-embedding-005")

# Use RETRIEVAL_QUERY for questions/queries
query_input = TextEmbeddingInput("How does BERT work?", task_type="RETRIEVAL_QUERY")

# Use RETRIEVAL_DOCUMENT for documents/passages
doc_input = TextEmbeddingInput("BERT uses masked language modeling...", task_type="RETRIEVAL_DOCUMENT")

# Single model, but task type changes the projection head behavior
query_emb = model.get_embeddings([query_input])[0].values  # 768-dim vector
doc_emb = model.get_embeddings([doc_input])[0].values    # 768-dim vector
⚠️ Why Task Type Matters

Questions and answers are phrased differently. Using a single SEMANTIC_SIMILARITY model for both degrades retrieval quality. The RETRIEVAL_QUERY and RETRIEVAL_DOCUMENT task types activate different projection behaviors optimized for asymmetric retrieval.

Key Code Examples

Doc2Vec Training on Custom Corpus

from gensim.models.Doc2Vec import Doc2Vec, TaggedDocument

# Tag each document with a unique ID
documents = [TaggedDocument(doc, [i]) for i, doc in enumerate(your_corpus)]

# Train with 8-dim embeddings, window size 3
model = Doc2Vec(documents, vector_size=8, window=3, min_count=1, workers=6)

# Infer vector for a new document (not in training set)
model.infer_vector(["human", "interface"])  # Returns 8-dim vector

Keras Text Classifier with Embedding Layer

# Using a TF Hub embedding model as a trainable layer
import tensorflow_hub as hub

embedding = "https://tfhub.dev/google/sentence-t5/st5-base/1"
hub_layer = hub.KerasLayer(embedding, trainable=True)

model = tf.keras.Sequential([
    hub_layer,                                 # Pre-trained embedding
    tf.keras.layers.Dense(16, activation='relu'),
    tf.keras.layers.Dense(1)                  # Binary classification
])
model.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy'])
