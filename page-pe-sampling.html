1.1 Model Selection & Configuration Setup

Prompt engineering is the design methodology of tailoring instructions to achieve optimal language task execution. Regardless of whether you use high-performance commercial models like Gemini 2.0 Flash in Vertex AI, GPT, Claude, or state-of-the-art open-source parameters like Gemma 2 or LLaMA 3, the raw prompt is only half of the story.

Every language model is governed by several core hyperparameters. Configuring these controls correctly is critical. If left at non-optimal defaults, you risk wasting compute budget, experiencing severe API latency spikes, or receiving structurally broken responses.

1.2 Output Length Limits Latency

An important configuration setting is the number of tokens to generate in a response. This behaves as a hard physical termination limit for token predictors:

⚠️ Token Constraints & Formatting
Reducing the max output length of the LLM **does not cause the model to write more succinctly**. Instead, the model simply stops predicting mid-sentence once the limit is hit, resulting in truncated, corrupted, and invalid structural formats (like broken JSON braces). To write succinctly, you must **actively instruct** the model to keep its reasoning short in the prompt text.

Generating more tokens requires more computation from the LLM, leading to higher energy consumption, slower response times (due to Time-To-First-Token and Inter-Token Latencies), and higher API pricing costs. This constraint is critical in multi-step loops like **ReAct**, where the model could enter redundant loops, generating unnecessary filler words.

1.3 Temperature & Softmax Probability Math Math

Under the hood, Large Language Models do not return a single word. Instead, for each step in a vocabulary $\mathcal{V}$, the neural network calculates raw logits, which are converted into a probability distribution over the next token candidate using the **Softmax Function**.

The **Temperature ($T$)** parameter scales these logits prior to the softmax calculation, altering the contrast of the probability distribution:

P(x_i) = \frac{\exp(z_i / T)}{\sum_{j} \exp(z_j / T)}
Softmax Temperature scaling
Low Temp (T → 0)

Amplifies the differences between token logits. The most probable token stands out with maximum certainty.

  • Deterministic output
  • T = 0 represents **greedy decoding** (picks highest logit)
High Temp (T → 1+)

Flattens the logits difference, making all tokens closer in likelihood. Encourages diverse, random, or creative phrasing.

  • Diverse, unexpected outputs
  • ⚠️ High risk of hallucinations and logic slips

1.4 Top-K & Top-P (Nucleus) Sampling Math

To prevent the model from picking extremely low-likelihood, non-sensical words at higher temperatures, models implement **Top-K** and **Top-P** sampling boundaries:

  • Top-K Sampling: Restricts the choice to the top $K$ most probable next tokens. A Top-K of 1 is equivalent to greedy decoding. Higher Top-K values give more creative output, while lower ones keep it strictly factual.
  • Top-P (Nucleus) Sampling: Selects from the smallest set of most likely tokens whose **cumulative probability** sums up to a threshold $P$ (ranging from 0 to 1). This is adaptive: if the model is confident in a few words, the pool of candidates remains extremely small. If the model is uncertain, the pool dynamically widens.
The Math Behind Nucleus Selection
For a threshold $P$, we sort all tokens $x_i$ descending by probability and select the top subset $J$ such that:
∑_{i ∈ J} P(x_i) ≥ P
All tokens not in $J$ are set to 0 probability before temperature sampling.

1.5 Putting Configurations Together Logic

If all three sampling configurations (Temperature, Top-K, and Top-P) are enabled, they are executed sequentially to choose the next predicted token:

1
Top-K Filter
The model sorts all vocabulary tokens by likelihood and retains only the top $K$ candidates.
2
Top-P Filter
Among the remaining candidates, it keeps the top subset whose cumulative probability reaches $P$, pruning out the rest.
3
Temperature & Sample
Finally, temperature scaling is applied to this highly restricted, valid candidate pool, and a token is stochastically sampled.

Boundary Behaviors & Irrelevance Rules

At extreme configuration settings, parameters cancel each other out:

  • If Temperature = 0: Top-K and Top-P become completely irrelevant. The model will always perform greedy decoding, choosing the highest probability token.
  • If Top-K = 1: Temperature and Top-P are overridden. Only a single token survives, behaving as greedy decoding.
  • If Top-P → 0: Only the single most probable token satisfies the threshold, rendering Temperature and Top-K irrelevant.

Recommended Baseline Parameters

Objective Temperature Top-P Top-K Behavior Result
Strictly Factual / Math 0.0 N/A N/A Greedy, completely repeatable code/logic.
Standard / Coherent 0.2 0.95 30 Coherent, highly accurate, low hallucination risk.
Highly Creative / Brainstorm 0.9 0.99 40 Extremely diverse text phrasing and creative variations.

1.6 Repetition Loop Failure Mode Bugs

A classic failure mode in Large Language Models is the **repetition loop bug** (also known as the filler words loop). This is a common issue where the model gets stuck in a cycle, repeatedly generating the same phrase, filler words, or empty sentences.

This is often caused by setting the Temperature too low (but non-zero) or restricted Top-K boundaries on long sequence contexts, forcing the model to re-evaluate its own highly repetitive self-attention parameters. To resolve this, increase the Temperature slightly or add **frequency/presence penalties** in the model parameters.
