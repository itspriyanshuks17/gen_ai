3.1 What is an Agent? Concepts

In its most fundamental form, a **Generative AI Agent** is defined as an application engineered to achieve specific objectives by perceiving its environment and strategically acting upon it using the tools at its disposal.

Unlike standalone language models that wait for prompt inputs, agents operate autonomously. Provided with a clear goal, an agent can reason about what it should do next, formulate a plan of actions, evaluate intermediate observations, and adjust its execution path proactive of human interventions.

3.2 Three Essential Architectural Elements Structure

The combination of components that drive an agent's behavior, actions, and decisions is termed its **Cognitive Architecture**. There are three essential elements in every agent:

  • The Model (Brain): The centralized decision-making unit (a language model) capable of instruction-based reasoning and parsing structured schemas.
  • The Tools: Bridge the gap with the outside world, enabling the model to retrieve real-time facts and actuate actions over external services (APIs).
  • The Orchestration Layer: The cyclic scheduling wrapper managing memory variables, state, tool routing registries, and logical planning transitions.

3.3 Models vs. Agents Comparison System

To grasp the engineering difference between core neural networks and agent systems, analyze this comparison:

Characteristic Generative Models Generative Agents
Knowledge Bounds Strictly limited to pretraining data (static library). Extended dynamically via real-time tool connections.
Context Lifecycle Single inference pass. No native session state tracking. Managed session and long-term memory registries.
Tool Capabilities No native tool integrations. Natively designed to invoke external tools (APIs).
Logic Operations Requires structural prompts for single logic blocks. Implements cyclic reasoning loops (ReAct, ToT, etc.).

3.4 Cognitive Architectures & The Chef Analogy Logic

Cognitive architectures map how an agent iteratively reasons about a target. Google's handbook uses a **Chef in a busy kitchen** analogy to illustrate this loop:

The Chef Cognitive Loop
1. Intake: The chef gathers info, checking the diner's ticket and looking inside the pantry for active ingredients. (Sensors & Data Stores).
2. Reasoning: The chef decides what dishes and flavors to build given these specific limits. (The Brain/Model).
3. Actuation: The chef chops vegetables, blends spices, and sears meat. (External Tool Actions).
4. Adjustment: The chef tastes the sauce, updates the plan if ingredients run out, and responds to immediate customer feedback. (The Orchestration/Memory).

3.5 The ReAct Planning Mechanism Orchestration

A classic orchestration pattern is **ReAct (Reason + Act)**. It coordinates a structured thought-action sequence:

1
Question
The original natural language query entered by the user.
2
Thought
The model reasons about what it should do next to achieve the target.
3
Action
The model makes a tool decision (e.g., selecting from `[Flights, Search, Code, None]`).
4
Action Input
The specific arguments generated by the model to call the tool API.
5
Observation
The raw return string from the tool API execution, fed back to the model context.
6
Final Answer
Once the target is solved, the model summarizes the aggregated facts back to the user.

3.6 LangChain & LangGraph Quickstart Code

To implement a live ReAct planning loop, use `langgraph` and `langchain` with a `gemini-2.0-flash-001` model tower to query search engines and location databases:

from langgraph.prebuilt import create_react_agent
from langchain_core.tools import tool
from langchain_community.utilities import SerpAPIWrapper
from langchain_community.tools import GooglePlacesTool
import os

# 1. Configure external API keys
os.environ["SERPAPI_API_KEY"] = "YOUR_SERPAPI_KEY"
os.environ["GPLACES_API_KEY"] = "YOUR_GOOGLE_PLACES_KEY"

# 2. Define custom tool wrapper methods
@tool
def search(query: str):
    """Use the SerpAPI to run a Google Search."""
    search_wrapper = SerpAPIWrapper()
    return search_wrapper.run(query)

@tool
def places(query: str):
    """Use the Google Places API to run a Google Places Query."""
    places_wrapper = GooglePlacesTool()
    return places_wrapper.run(query)

# 3. Instantiate model and bind tools
model = ChatVertexAI(model="gemini-2.0-flash-001")
tools = [search, places]

# 4. Construct the autonomous ReAct agent loop
agent = create_react_agent(model, tools)

# 5. Stream execute a multi-stage request
query = "Who did the Texas Longhorns play in football last week? What is the address of their stadium?"
input_state = {"messages": [("human", query)]}

for state in agent.stream(input_state, stream_mode="values"):
    message = state["messages"][-1]
    message.pretty_print()
