2.1 Dual Encoder Architecture Two-Tower

Modern embedding models typically leverage a **Dual Encoder (Two-Tower) neural network architecture** to map separate modalities or asymmetric inputs into a single, shared latent space.

This setup trains two distinct neural network encoders, with sub-architectures configured depending on how weights are shared:

1
Text Search Dual Encoder
One neural network tower encodes the query string, while the other tower encodes the document chunks. The towers project both into a shared vector manifold.
2
Multimodal Dual Encoder
An image-encoder tower (e.g., Vision Transformer) and a text-encoder tower map visuals and search phrases into the exact same vector space.
3
Weight-Sharing Configurations
Towers can be **symmetric (sharing all weights)** for identical task alignments, or **asymmetric (separate layers)** when inputs differ drastically in size, structure, or modality.

2.2 Contrastive Loss Objective

The loss function used to train embedding neural networks is typically a variation of **Contrastive Loss** or **InfoNCE Loss**. The training objective takes input tuples in the form of:

Tuple Input Tuple = < Input_anchor, Positive_target, [Optional] Negative_targets >
Positive Examples Attraction

Brings positive pairs (e.g., a question and its correct answer chunk) closer together in the vector space by maximizing their cosine similarity.

Negative Examples Repulsion

Pushes negative target examples (e.g., incorrect or unrelated text chunks) far apart, creating a distinct margin between semantically different objects.

2.3 Pre-training & Fine-Tuning Stages

Similar to foundation models, building state-of-the-art embedding models relies on a two-stage training loop:

1
Stage 1: Pre-training (Unsupervised)
The neural networks are trained from scratch on massive, raw, unlabeled corpora using self-supervised objectives (e.g., Masked Language Modeling) to learn general syntactical representation and language knowledge.
2
Stage 2: Fine-Tuning (Supervised)
The pre-trained model is initialized and fine-tuned on labeled dataset configurations to optimize performance for specific downstream tasks.
Leveraging Foundation Models
Rather than executing costly pre-training from scratch, modern practitioners initialize embedding models directly from large pre-trained foundation model backbones (such as **BERT, T5, GPT, Gemini, or CoCa**). This leverages massive knowledge bases learned from billions of pre-training tokens.

2.4 Labeled Dataset Creation Strategies

Fine-tuning embedding models requires rich datasets of positive and negative tuples. High-quality datasets are created using four primary methods:

  • Human Labeling: Experts manually annotate pairs (e.g., medical specialists matching patient queries to reference documents). This yields extremely high quality but is highly expensive and slow.
  • Synthetic Dataset Generation: Utilizing powerful Large Language Models (LLMs) to automatically generate massive synthetic question-document pairs. (e.g., Google DeepMind's **Gecko** model leverages LLMs to compile vast, high-quality synthetic datasets).
  • Model Distillation: Training a smaller, faster embedding model to mimic the vector representations and similarity outputs of a much larger, computationally intensive teacher model.
  • Hard Negative Mining: Finding "hard negatives"—documents that look highly similar to the query on a surface/keyword level but are actually irrelevant—and explicitly training the model to push them far apart.

2.5 Downstream Classifiers & Custom Models

To use embedding representations for downstream tasks (like text classification, sentiment analysis, or named entity recognition), extra dense neural layers and a softmax output layer are placed directly on top of the embedding model's output vector.

Model Tuning Configurations

Frozen Embeddings

The embedding model parameters are locked. Only the weights of the top classifier layers are updated during training.

  • Ideal when the training dataset is small
  • Prevents overfitting of base layers
End-to-End Fine-Tuning

The embedding layers are left trainable. Both the base embedding weights and the classification heads are optimized together.

  • Best when training datasets are massive
  • Adapts the vector space to downstream tasks

Keras Classifier with Trainable TF-Hub Layers

This code example builds a custom classifier model using TensorFlow and Keras, loading a pre-trained trainable BERT encoder layer directly from TensorFlow Hub:

import tensorflow as tf
import tensorflow_hub as hub

# Load pre-trained BERT encoder from TensorFlow Hub
tfhub_link = "https://tfhub.dev/tensorflow/bert_en_uncased_L-12_H-768_A-12/4"

class Classifier(tf.keras.Model):
    def __init__(self, num_classes):
        super(Classifier, self).__init__(name="prediction")
        # Wrap the TF-Hub layer in KerasLayer and mark as trainable
        self.encoder = hub.KerasLayer(tfhub_link, trainable=True)
        self.dropout = tf.keras.layers.Dropout(0.1)
        self.dense = tf.keras.layers.Dense(num_classes)

    def call(self, preprocessed_text):
        # 1. Forward pass through BERT encoder
        encoder_outputs = self.encoder(preprocessed_text)
        # 2. Extract pooled_output ([CLS] contextual vector)
        pooled_output = encoder_outputs["pooled_output"]
        # 3. Regularize and map to classification categories
        x = self.dropout(pooled_output)
        return self.dense(x)

# Compile and train custom classifier
model = tf.keras.Sequential([
    Classifier(num_classes=1)
])
model.compile(
    optimizer='adam',
    loss=tf.keras.losses.BinaryCrossentropy(from_logits=True),
    metrics=['accuracy']
)
